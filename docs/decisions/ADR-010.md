# ADR-010：关系图用 vis-network 浏览器组件 + JSON API

> 日期：2026-08-06

## Status

已接受（Accepted）

## Context

需求包含客户关系图：以某客户为中心展示其关联的人、保单、工作事件、文件。展示要求是桌面端有限层级展开，手机端用单层列表替代（reference-analysis §2 的需求既定）。

参考分析 §2 完成了选型对比，结论明确：

- 采用 vis-network（Apache-2.0/MIT 双许可）：零构建 script 标签集成，最贴合「Django 模板 + HTMX/Alpine」的服务端渲染栈；内置 `layout.hierarchical` 与 clustering/openCluster，正好覆盖「有限层级展开」；触摸事件内置，平板仍可用。
- 拒绝 Cytoscape.js（重在图论分析/数千节点，本场景大材小用）、G6 与 relation-graph（面向框架生态、需打包器）、d3-force（无现成交互组件）。
- 手机端不渲染 Canvas 图，用单层列表替代，避免触屏可访问性与性能成本。

关系图数据量级为几十个节点、最多三层，完全在 SQL 查询能力内，不需要图数据库。引入图数据库（如 Neo4j）会破坏 ADR-001 的单库部署，且当前数据规模无收益。

## Decision

- 关系图渲染使用 vis-network 浏览器组件，以 UMD 单文件方式引入（本地托管，不依赖外网 CDN）。
- 图数据通过专门的 JSON 端点输出：按需返回中心节点、其直接关联的客户/保单/事件/文件，以及层级展开请求的下一层。该端点为 ADR-007 的「确需 JSON」例外。
- 桌面端：用 `layout.hierarchical` 做有限层级（最多三层）展示，节点展开通过 clustering/openCluster 按需拉取，避免一次渲染全图。
- 手机端：不渲染 Canvas 图，展示单层列表（关系类型分组），并提供进入详情的入口。
- 图数据端点做权限过滤（与页面同一套 requires_permission，ADR-004），只返回当前用户有权查看的节点。
- 不引入图数据库、不引入前端框架。

## Consequences

正面：

- 零构建集成，符合 ADR-007 技术栈，静态单文件易于自托管。
- 有限层级展开符合需求与数据规模，性能可控。
- 手机端列表方案避免触屏 Canvas 的可用性问题。

负面：

- 超过三层或数百节点的极端数据量会出现性能下降，超出设计范围，需提示而不是硬撑。
- JSON 端点需要专门的接口测试与权限测试（docs/testing.md）。
- vis-network 以 script 引入，依赖它的版本固定与本地托管，避免外网依赖。

## 实现要点

- JSON 端点的节点类型映射、层级深度上限、分页方式写入接口文档。
- 图的加载失败降级为列表：vis-network 脚本未加载时不白屏。
- 关系类型颜色与图标映射集中在模板或配置文件，手机列表与桌面图共用同一份语义。
- 展开请求带深度参数，服务端限制最大深度并返回截断提示。

## 被否决的备选

- Cytoscape.js：图论分析向、面向数千节点，本场景几十个节点大材小用（参考分析 §2 结论）。
- G6 / relation-graph：面向框架生态、需打包器，与 Django 模板直出冲突。
- 图数据库（如 Neo4j）：破坏 ADR-001 的单库部署，几十节点规模无收益。
- 手机端渲染 Canvas 图：触屏可访问性与性能成本高，用单层列表替代（参考分析 §2 结论）。
