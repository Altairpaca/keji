# ADR-008：Tailwind 构建（独立二进制或 npm，生产无 Node 运行时）

> 日期：2026-08-06

## Status

已接受（Accepted）

## Context

样式方案需要满足两个约束：

1. 与 ADR-007 的服务端模板栈契合，不引入组件框架绑定。
2. 生产环境不希望依赖 Node 运行时。部署者是自托管的小团队，容器里多一个 Node 进程就多一个攻击面与升级负担。

Tailwind 提供两条可行的编译路径：官方独立二进制（standalone CLI，纯 Go 编译的单一可执行文件）与 npm 包。两者产物都是纯 CSS 文件。

选型的取舍核心是「编译产物归谁」。如果生产运行时需要 Node 才能产 CSS，等于把构建链塞进部署容器；如果编译在开发/CI 完成、产物随版本走，生产就只是一个静态文件目录。后者与 ADR-001 的单容器部署最契合。

## Decision

- 样式采用 Tailwind CSS，通过编译步骤生成静态 CSS 文件。
- 编译方式二选一，按 CI 环境可用性选定并固定一种，避免两套都维护：
  - 优先：Tailwind standalone 二进制（`tailwindcss` 单文件），CI 与本地开发共用同一脚本 `scripts/tailwind-build`。
  - 备选：npm 包（`npm ci && npx tailwindcss -i ... -o ...`）。
- 编译产物（`static/dist/app.css`）提交进版本库或由 CI 构建步骤产出，生产部署时直接服务静态文件。
- 生产运行时不需要 Node，也不需要 tailwind 包；只有开发与 CI 需要编译工具链。
- 开发阶段用 watch 模式自动重编译，配合 Django 的 static 收集。
- 锁定额外依赖版本：standalone 二进制以固定版本号下载，npm 以 `package-lock.json` 固定，两侧版本在 CI 中一致性校验。

## Consequences

正面：

- 生产镜像不含 Node 运行时，攻击面小、镜像小。
- 纯静态 CSS 产物，与 Django staticfiles 集成简单。
- 开发与生产产物一致，避免「开发时 JIT、生产时不同」的差异。

负面：

- 样式变更必须重新编译，忘了编译会出现「代码改了、样式没变」的困惑，用 CI 校验编译产物是否最新来兜底。
- standalone 二进制版本与 npm 包版本可能不一致，锁定版本号并写进构建脚本。
- 动态类名（拼接 class 字符串）会被内容扫描漏掉，需要遵守 Tailwind 的安全列表约定。

## 实现要点

- CI 步骤：重跑编译后比对产物哈希，不一致则失败（防止「忘了提交 CSS」）。
- 内容扫描路径必须包含模板目录与所有静态 JS 目录，新增模板文件不会漏扫。
- 手机端响应式断点随组件约定，避免类名散乱。
- 编译产物文件名带内容哈希，配合 Django static 版本化，避免浏览器缓存旧样式。

## 被否决的备选

- 生产运行时用 Node 跑 Tailwind 或 PostCSS：违背「生产无 Node」约束，容器多一个运行时与依赖升级负担。
- 手写原生 CSS：样式一致性差、组件复用难，维护成本随规模上升。
- Tailwind Play CDN 或外网 CDN 加载：生产引外部依赖，违反本地托管原则，离线壳（ADR-014）也无法缓存。
