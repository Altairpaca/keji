# ADR-013：seed_demo 虚构数据命令（demo- 前缀标记，可重置，无真实 PII）

> 日期：2026-08-06

## Status

已接受（Accepted）

## Context

演示与开发环境需要可复现的示例数据：客户、保单、理赔、文件、任务、关系图。这些数据必须满足三点：

1. 无真实 PII：绝不能使用真实客户的姓名、电话、证件号、病历。虚构数据产生于命令本身，不读取任何外部源。
2. 可重置：演示完、测试完要能一键清空恢复干净环境，不污染真实数据。
3. 可识别：示例数据必须与真实数据清晰区分，避免「把演示数据当真实数据」的误操作。

同时要防止两个反例：把演示数据直接写进迁移文件（污染所有环境），或提供「导入真实客户表」的便利功能（鼓励生产数据进入开发库）。

演示环境与测试环境共用一套数据的风险在于：测试断言可能依赖演示数据的存在，导致「换个空库就挂」。因此 seed_demo 与 pytest 的 fixtures 必须解耦，演示数据只服务人工演示，不服务自动化测试。

## Decision

- 提供 `seed_demo` 管理命令，向数据库插入虚构演示数据。
- 标记约定：演示数据通过字段值或标签统一带 `demo-` 前缀（如客户名 `demo-张三`、标签 `demo-演示`），并支持在客户、保单、文档等主要模型上查询出所有演示数据。
- 提供重置能力：`seed_demo --reset` 先清除全部 `demo-` 前缀标记的数据（含其文件与关联），再重新生成，保证幂等可重复。
- 演示数据写入独立的可区分通道：命令显式设置 `created_by` 为演示用户或标记 `source=demo` 元数据字段。
- 生成内容覆盖关系图场景：至少包含一个中心客户及多类关联（配偶、子女、保单、理赔材料、工作事件），保证 ADR-010 的关系图有可演示素材。
- 生产环境默认不执行；执行需显式传参并打印警告。
- 不提供任何「导入真实数据为演示」的功能。
- 命令内部禁止访问网络与外部文件，所有姓名、号码、照片均为内置生成或本地示例文件。

## Consequences

正面：

- 演示与开发环境可一键初始化、一键重置。
- `demo-` 前缀让示例数据与真实数据在任何界面都可分辨。
- 无真实 PII 进入任何环境，符合隐私边界（docs/security.md）。

负面：

- 维护一套虚构数据生成逻辑有持续成本，字段变动时需要同步更新命令。
- `demo-` 前缀约定依赖执行纪律，需要在文档与代码评审中强调。

## 实现要点

- 重置逻辑复用删除协议（ADR-006）的关联清理路径，避免残留孤儿记录。
- 演示图片使用内置生成的合成图，不读取用户真实图片目录。
- 命令输出日志列出创建与清除的对象数量，便于演示时核对。
- demo 数据的文件与缩略图同样落存储层 `originals/`、`thumbnails/`，演示存储管线真实路径。

## 被否决的备选

- 演示数据写进迁移文件：污染所有环境，测试断言会依赖迁移数据，新库与演示库行为不一致。
- 从真实客户导入为演示：鼓励 PII 进入开发与演示环境，直接违反无 PII 前提。
- 无标记的随机生成数据：无法区分演示与真实，重置命令有误删真实数据的风险。
