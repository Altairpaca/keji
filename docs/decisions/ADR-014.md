# ADR-014：最小 PWA（壳缓存 + 离线错误页，不做离线编辑）

> 日期：2026-08-06

## Status

已接受（Accepted）

## Context

手机端是主要使用场景（ADR-009），用户期望能「安装到主屏幕」并有一定离线韧性：弱网环境下打开应用至少能看到可用的壳，而不是一片空白。

评估了完整 PWA 离线能力（离线编辑、本地队列、全量缓存数据）。这类方案会让客户端与服务器持有两份数据副本，同步冲突时可能用旧数据覆盖新数据（ADR-009 已明确「数据一致性优先于完全离线」的原则）。对单管理员加少量用户的自托管系统，复杂离线同步的收益与风险不成比例。

另一个约束来自部署形态：自托管站点不一定部署在固定域名上，HTTPS 是 Service Worker 的硬前提。因此最小 PWA 的实现依赖部署指南里对 TLS 的要求，内网部署也建议启用 TLS（见 docs/security.md）。

## Decision

实现最小 PWA：

- 提供 `manifest.json` 与图标：应用可安装到主屏幕，独立窗口打开。
- 提供 Service Worker，仅做两件事：
  - 缓存应用壳（manifest、图标、CSS、JS、离线错误页）。
  - 网络请求失败时返回离线错误页，明确提示「当前离线，无法操作」，而不是渲染过期内容。
- 不做离线编辑：没有本地持久化编辑队列、没有离线创建/修改数据的机制，避免旧数据覆盖新数据。
- Service Worker 采用版本化缓存与更新策略：发布新版本时淘汰旧缓存，避免「壳是新的、内容逻辑是旧的」的错位。
- 上传行为保持 ADR-009 的在线语义：断网时提示用户重试，不假装同步。

## Consequences

正面：

- 低实现成本获得「可安装 + 离线有壳」的体验提升。
- 不会引入双副本同步的一致性风险。
- 更新策略简单，部署后旧缓存自动失效。

负面：

- 离线只能看壳与错误页，不能浏览已缓存内容，离线体验有限。
- Service Worker 的缓存淘汰逻辑需要测试，避免升级后缓存残留。
- HTTPS 是 PWA 前置条件，自托管需要正确配置 TLS（内网部署也建议启用，见 docs/security.md）。

## 实现要点

- Service Worker 只在生产静态资源路径注册，开发环境跳过，避免缓存干扰开发迭代。
- 缓存名带版本号，发布流程自动递增版本并触发更新。
- 离线错误页不包含动态数据，保证任意时刻可渲染。
- SW 注册与更新流程纳入 E2E 测试（docs/testing.md），确认升级后不残留旧缓存。
- 离线错误页提供刷新按钮与在线状态提示，弱网下引导用户重试。
- manifest 的 `display` 与主题色沿用既有设计变量，不单独造一套品牌。

## 被否决的备选

- 完整离线编辑加本地队列：双副本一致性风险，旧数据覆盖新数据，违背 ADR-009 原则。
- 把业务数据全量缓存进浏览器：敏感数据常驻客户端缓存，删除与更新难以同步，隐私风险大。
- 不做 PWA：手机端「安装到主屏」是明确需求，缺失会明显削弱使用体验。
