# 测试策略（testing）

> 日期：2026-08-06 ｜ 状态：蓝图。W2 起执行；与 AGENTS.md 的 TDD 约定、docs/security.md（安全测试范围）、docs/data-model.md（校验节）配套。

## 1 测试原则

- 每个 app 的测试独立放在 `apps/<name>/tests/`，不跨 app 耦合（AGENTS.md）。
- 分层测试：模型方法、服务层函数、视图、表单、安全各归其位，避免「一个测试测到底」。
- 数据库读写经 services 层进出，测试随之优先测服务层，视图只测编排与权限。
- 演示数据（seed_demo，ADR-013）不进入自动化测试，测试用独立 fixtures，避免「换空库就挂」。

## 2 TDD：RED → GREEN → REFACTOR

- 规则：**先写失败测试**，确认 RED（断言失败原因明确），再最小实现到 GREEN，最后清理。
- 每笔改动先补测试再动实现；涉及模型改动的，先写模型/服务测试再生成迁移。
- 禁止「先实现后补测试」，也禁止「实现和测试一起写完直接跑绿」（RED 从未发生）。
- 提交前该 app 测试全绿，且不能以跳过/修改既有测试来换绿。

## 3 目录布局与命名约定

每个 app 的 `tests/` 目录：

```
apps/<name>/tests/
├── __init__.py
├── conftest.py          # 本 app 专属 fixtures
├── test_models.py       # 模型方法、状态流转、软删除、约束
├── test_views.py        # 页面渲染、上下文、HTMX 片段、重定向
├── test_forms.py        # 表单校验、字段清洗、错误信息
├── test_services.py     # 服务层函数与事务边界
├── test_security.py     # 权限位 403、未授权对象访问、敏感操作
└── test_api.py          # JSON 端点（关系图、上传等）
```

- 命名：测试函数 `test_<行为描述>`，一个函数只断言一件事。
- 全局 fixtures 放项目级 `conftest.py`（登录用户、角色矩阵、存储后端 stub）。
- 上传/文件相关测试用临时媒体目录，不污染真实 `media/`。

## 4 Fixtures 策略

- **角色 fixture**：`admin_user`、`normal_user_all_perms`、`normal_user_minimal`（零权限）三种基础角色，安全测试复用。
- **数据 fixture**：客户/保单/理赔/文件的对象工厂（factory 函数或 fixture 级联），对象级联组装，不在模块内裸造对象。
- **存储 fixture**：`StorageBackend` 换成临时目录实现，测试断言文件落在预期存储键。
- **解耦原则**：fixture 只造被测对象所需的最小数据；demo 数据与测试数据彻底分开。
- 时间相关测试用冻结时间（freezegun 或依赖注入），避免「待办逾期」类测试随日期漂移。

## 5 覆盖范围（§26 最低自动化测试范围）

- 认证：登录/登出成功与失败路径、登录失败限流触发。
- 权限：每个权限位的 403 断言、未认证重定向登录、无 UI-only 门禁抽查。
- 客户：CRUD、软删除进回收站、恢复、永久删除一致性（记录/关联/文件/审计）。
- 关系：客户关系 7 类型创建与查询、关系图 JSON 端点权限过滤。
- 活动时间线：工作事件/沟通记录创建、时间线聚合顺序、文件关联。
- 文件：上传去重（checksum）、下载、权限拒绝、软删与恢复、敏感文件审计。
- 路径安全：路径穿越（`..`、绝对路径）、危险文件名（`../../x`、控制字符）拒绝。
- 上传边界：超限文件拒绝、类型/魔数不匹配拒绝、SVG 拒绝、压缩炸弹上限。
- 保单：状态流转与 PolicyStatusHistory 记录、投保人/被保险人角色。
- 理赔：材料状态机全路径（待上传→已上传→已审核/需补交/已退回）、ZIP 导出权限。
- 沟通与待办：沟通记录 CRUD、待办逾期状态、首页工作队列聚合。
- 搜索：全局搜索中文子串命中、跨模型合并排序、空查询。
- 批量导入/导出：CSV 导入字段校验、导出文件权限。
- 审计：登录/增删改/恢复/永久删除/敏感文件操作均落 AuditLog。
- 备份：备份命令产出 manifest、restore 脚本还原到空库并核对记录数。
- 页面渲染：关键页面 200、模板上下文、HTMX 片段可渲染。
- 未授权对象访问：他人/软删对象直接 URL 访问返回 404/403。
- CSRF：无 token 的 POST 被拒。
- 空库迁移：全新数据库从零迁移可跑通（CI 空库作业）。

## 6 Playwright E2E 计划

- 浏览器自动化入口：`pytest -m e2e`，Playwright project 分两个：
  - **desktop project**（Chromium，桌面视口）：客户 CRUD、关系图展开、回收站、理赔材料流程、全局搜索。
  - **mobile project**（Chromium mobile 视口或 webkit）：多选上传流程、PWA 安装壳、单层关系列表、响应式导航。
- E2E 覆盖关键用户路径，不做 UI 细节断言（细节交给视觉 QA）。
- E2E 用独立测试库与种子数据，跑完清理，不依赖手动步骤。

## 7 视觉 QA 循环

- 每轮界面改动后跑视觉 QA：截图对比基线（desktop + mobile 双视口）。
- 基线存 `docs/screenshots/`（虚构数据，ADR-013），差异人工确认：结构变化更新基线，意外回归修复。
- 中文字体渲染、缩略图模糊、表单错误态纳入视觉清单。

## 8 质量门禁

```bash
# 提交前必须全绿
pytest && ruff check . && ruff format --check . && mypy keji
```

- CI 与本地同一套命令；`ruff` 零告警、`mypy` 零告警（AGENTS.md：禁止 `# type: ignore` 与 `cast()` 绕行）。
- 另加两项：Tailwind 编译产物哈希校验（ADR-008）、空库迁移作业（§5 最后一项）。

## 9 覆盖率阈值建议

- 全局行覆盖率目标 **≥ 80%**，关键路径加严：
  - `apps/*/services.py`（事务与业务规则）：≥ 85%。
  - `apps/*/security.py` / 权限装饰器：100% 覆盖 11 个权限位分支。
  - 上传校验与永久删除一致性路径：100%。
- 覆盖率作为趋势指标而非单一门槛：新代码必须带测试，红线只在「显著回退」时阻塞。
